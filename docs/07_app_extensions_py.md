# Документация: app/extensions.py

## Назначение

Файл `app/extensions.py` содержит **глобальные экземпляры расширений Flask**. Это центральный модуль, где создаются объекты расширений до их привязки к приложению. Паттерн позволяет избежать циклических импортов и обеспечивает единую точку определения всех расширений.

## Структура

### Импорт расширений
```python
from flask_sqlalchemy import SQLAlchemy
from flask_migrate import Migrate
from flask_login import LoginManager
```

### Глобальные экземпляры
```python
db = SQLAlchemy()
migrate = Migrate()
login_manager = LoginManager()
```

Каждый экземпляр создаётся **без привязки к приложению** — это ключевой момент паттерна Application Factory.

## Компоненты

### 1. `db = SQLAlchemy()`

**Назначение**: ORM-движок для работы с базой данных.

**Использование в проекте**:
- Инициализируется в `app/__init__.py`: `db.init_app(app)`
- Используется в `app/models.py` как `db.Model` для определения таблиц
- Предоставляет `db.session` для выполнения запросов
- Предоставляет `db.engine` для прямых соединений

**Методы и свойства**:
| Элемент | Описание |
|---------|----------|
| `db.Model` | Базовый класс для всех моделей |
| `db.session` | Сессия для CRUD-операций |
| `db.engine` | Движок подключения к БД |
| `db.create_all()` | Создание таблиц из моделей |
| `db.session.get(Model, id)` | Получение записи по ID |

### 2. `migrate = Migrate()`

**Назначение**: Управление миграциями базы данных через Alembic.

**Использование в проекте**:
- Инициализируется в `app/__init__.py`: `migrate.init_app(app, db)`
- Позволяет изменять схему БД без потери данных
- Используется через CLI: `flask db migrate`, `flask db upgrade`

**Команды Flask-Migrate**:
```bash
# Создать миграцию
flask db migrate -m "описание изменений"

# Применить миграцию
flask db upgrade

# Откатить миграцию
flask db downgrade

# Показать историю
flask db history
```

### 3. `login_manager = LoginManager()`

**Назначение**: Управление аутентификацией и сессиями пользователей.

**Использование в проекте**:
- Инициализируется в `app/__init__.py`: `login_manager.init_app(app)`
- Настраивается в `app/__init__.py`:
  ```python
  login_manager.login_view = "web.login_page"
  login_manager.login_message = "Пожалуйста, войдите в систему"
  ```
- Определяет поведение при неавторизованном доступе:
  - Перенаправляет на страницу входа
  - Показывает сообщение об ошибке

**Методы и свойства**:
| Элемент | Описание |
|---------|----------|
| `@login_manager.user_loader` | Callback для загрузки пользователя по ID |
| `login_manager.login_view` | Имя маршрута страницы входа |
| `login_manager.login_message` | Сообщение при перенаправлении на вход |
| `login.current_user` | Текущий авторизованный пользователь |
| `login.login_user()` | Вход пользователя |
| `login.logout_user()` | Выход пользователя |
| `login.login_required` | Декоратор для защиты маршрутов |

## Ключевая логика

### Паттерн «Extension Initialization Without App»
```
1. Создать пустые экземпляры (без app)
2. Импортировать в app/__init__.py
3. Вызвать init_app(app) для каждого
```

Это позволяет:
- Избегать циклических импортов (models.py импортирует db, __init__.py импортирует models)
- Создавать несколько экземпляров приложения для тестирования
- Разделять определение расширений и их конфигурацию

### Почему именно так?

| Подход | Проблема | Решение |
|--------|----------|---------|
| `db = SQLAlchemy(app)` | Циклический импорт с models.py | Создать без app, инициализировать позже |
| `db` в каждом файле | Дублирование | Единый файл extensions.py |

## Зависимости и связи

| Элемент | Тип связи | Описание |
|---------|-----------|----------|
| `app/__init__.py` | Инициализация | Вызывает `init_app()` для всех расширений |
| `app/models.py` | Использование | Наследует `db.Model`, использует `db.session` |
| `app/auth.py` | Использование | Flask-Login для аутентификации |
| `run.py` | Косвенная связь | Запускает приложение, которое инициализирует расширения |

## Важные замечания

1. **Пустая инициализация**: Экземпляры создаются без параметров — вся настройка происходит в `__init__.py`.
2. **Глобальные объекты**: Это не настоящие глобальные переменные — они привязываются к приложению при `init_app()`.
3. **Только 3 расширения**: Проект использует минимальный набор Flask-расширений для простоты.
4. **Тестирование**: В тестах (`tests/conftest.py`) создаётся отдельный экземпляр приложения с SQLite, который также инициализирует эти расширения.
