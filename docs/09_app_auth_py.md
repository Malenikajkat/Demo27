# Документация: app/auth.py

## Назначение

Файл `app/auth.py` — это модуль **аутентификации**, содержащий функции для хеширования и проверки паролей. Использует библиотеку Werkzeug (ядро Flask) для безопасного хранения паролей пользователей.

## Структура

### Импорт
```python
from werkzeug.security import generate_password_hash, check_password_hash
```

### Функция `hash_password(password: str) -> str`

**Назначение**: Хеширование пароля перед сохранением в базу данных.

**Параметры**:
| Параметр | Тип | Описание |
|----------|-----|----------|
| `password` | `str` | Пароль в открытом виде |

**Возвращает**: `str` — хеш пароля

**Алгоритм**: PBKDF2 + SHA256 (по умолчанию Werkzeug)

**Пример**:
```python
from app.auth import hash_password

hashed = hash_password("my_secret_password")
# hashed = "pbkdf2:sha256:260000$...длинная_строка..."

# Сохранение в БД
user = User(login="admin", password_hash=hashed)
db.session.add(user)
```

### Функция `verify_password(password: str, password_hash: str) -> bool`

**Назначение**: Проверка пароля по хешу при авторизации.

**Параметры**:
| Параметр | Тип | Описание |
|----------|-----|----------|
| `password` | `str` | Введённый пароль |
| `password_hash` | `str` | Хеш из базы данных |

**Возвращает**: `bool` — True если пароль совпадает

**Пример**:
```python
from app.auth import verify_password

# Загрузка хеша из БД
user = db.session.get(User, 1)
if verify_password("my_secret_password", user.password_hash):
    login_user(user)
else:
    raise ValueError("Неверный пароль")
```

## Ключевая логика

### Безопасность паролей

| Аспект | Реализация |
|--------|------------|
| **Алгоритм** | PBKDF2 (Password-Based Key Derivation Function 2) |
| **Хеш-функция** | SHA-256 |
| **Итерации** | 260,000 (по умолчанию Werkzeug) |
| **Соль** | Автоматически генерируется Werkzeug |
| **Обратимость** | НЕОБРАТИМО — нельзя восстановить пароль из хеша |

### Почему не хранить пароли в открытом виде?

1. **Утечка БД**: При взломе базы все пароли будут скомпрометированы
2. **Внутренние угрозы**: Сотрудники с доступом к БД не смогут видеть пароли
3. **Повторное использование**: Пользователи часто используют один пароль на нескольких сайтах

### Процесс регистрации

```
Ввод пароля → hash_password() → Сохранение в БД
```

### Процесс авторизации

```
Ввод пароля → Загрузка хеша из БД → verify_password() → Вход / Ошибка
```

## Зависимости и связи

| Элемент | Тип связи | Описание |
|---------|-----------|----------|
| `werkzeug.security` | Зависимость | Библиотека для хеширования |
| `app/services/auth_service.py` | Использует | Вызывает `hash_password()` и `verify_password()` |
| `app/services/user_service.py` | Использует | Вызывает `hash_password()` при создании пользователя |
| `app/models.py` (User) | Данные | `password_hash` поле модели User |
| `scripts/check_password.py` | Использует | Проверяет хеш пароля |

## Важные замечания

1. **Один файл, две функции**: Модуль намеренно минималистичен — вся бизнес-логика авторизации находится в `auth_service.py`.
2. **Werkzeug по умолчанию**: Использует PBKDF2. В новых версиях Werkzeug можно использовать `scrypt` или `argon2` для большей безопасности.
3. **Не обращаться напрямую**: Всегда используйте сервисы (`auth_service.py`, `user_service.py`) вместо прямого вызова функций.
4. **Соль**: Werkzeug автоматически генерирует и хранит соль вместе с хешем — отдельное управление солью не требуется.
