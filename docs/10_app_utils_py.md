# Документация: app/utils.py

## Назначение

Файл `app/utils.py` содержит **вспомогательные функции** для трансформации данных, в первую очередь для работы с заметками (Notes API). Реализует требования задания 5 (API.md) по форматированию ответа API.

## Структура

### Функция `format_note_id(note_id: int) -> str`

**Назначение**: Форматирование числового ID заметки в строку с ведущими нулями.

**Параметры**:
| Параметр | Тип | Описание |
|----------|-----|----------|
| `note_id` | `int` | Числовой ID из базы данных |

**Возвращает**: `str` — строка ID шириной 5 символов

**Примеры**:
```python
format_note_id(1)    # "00001"
format_note_id(42)   # "00042"
format_note_id(12345) # "12345"
```

**Реализация**: Использует `str.zfill(5)` — дополняет строку нулями слева до длины 5.

**Требование API.md**: ID должен быть в формате "00001", а не "1".

### Функция `format_date(date_obj) -> str`

**Назначение**: Форматирование объекта даты в строку российского формата.

**Параметры**:
| Параметр | Тип | Описание |
|----------|-----|----------|
| `date_obj` | `datetime.date` / `datetime.datetime` | Объект даты |

**Возвращает**: `str` — дата в формате "ДД.ММ.ГГГГ"

**Примеры**:
```python
format_date(datetime(2025, 3, 15))   # "15.03.2025"
format_date(datetime(2025, 1, 5))    # "05.01.2025"
```

**Реализация**: Использует `strftime("%d.%m.%Y")`.

**Требование API.md**: Дата должна быть в формате "ДД.ММ.ГГГГ", а не ISO-формате.

### Функция `build_note_response(note, login: str) -> dict`

**Назначение**: Сборка JSON-объекта ответа для одной заметки с трансформацией всех полей.

**Параметры**:
| Параметр | Тип | Описание |
|----------|-----|----------|
| `note` | `Note` (SQLAlchemy модель) | Объект заметки из БД |
| `login` | `str` | Логин автора заметки |

**Возвращает**: `dict` — словарь для JSON-ответа

**Структура возвращаемого словаря**:
```python
{
    "id": "00001",              # format_note_id(note.note_id)
    "title_user": "Заголовок - login",  # f"{note.title} - {login}"
    "content": "Текст заметки",
    "formatted_date": "15.03.2025"       # format_date(note.created_at)
}
```

**Поля ответа**:

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `str` | ID заметки (5-значная строка) |
| `title_user` | `str` | Заголовок + логин автора |
| `content` | `str` | Текст заметки |
| `formatted_date` | `str` | Дата создания в формате ДД.ММ.ГГГГ |

**Пример использования**:
```python
# В blueprint или view
note = db.session.get(Note, 1)
user = db.session.get(User, note.id_user)
response = build_note_response(note, user.login)
# {
#     "id": "00001",
#     "title_user": "Моя заметка - admin",
#     "content": "Текст...",
#     "formatted_date": "15.03.2025"
# }
```

## Ключевая логика

### Соответствие API.md (Задание 5)

| Требование API.md | Реализация |
|-------------------|------------|
| ID в формате "00001" | `format_note_id()` через `zfill(5)` |
| Поле `title_user` = "title - login" | `build_note_response()` через f-string |
| Дата в формате "ДД.ММ.ГГГГ" | `format_date()` через `strftime` |
| Поле `content` без изменений | Прямое копирование |

### Разделение трансформации

Функции разделены по принципу единственной ответственности:
- `format_note_id` — только форматирование ID
- `format_date` — только форматирование даты
- `build_note_response` — сборка итогового объекта

Это позволяет переиспользовать функции независимо.

## Зависимости и связи

| Элемент | Тип связи | Описание |
|---------|-----------|----------|
| `app/blueprints/notes.py` | Использует | Вызывает `build_note_response()` |
| `app/dtos/note_dto.py` | Аналог | NoteDTO делает похожую трансформацию |
| `Zadanie/API.md` | Требования | Определяет формат ответа |
| `app/views/note_view.py` | Использует | Вызывает функции трансформации |

## Важные замечания

1. **Дублирование с DTO**: `app/dtos/note_dto.py` содержит аналогичную логику трансформации через `NoteDTO`. Это может быть избыточным.
2. **Нет валидации**: Функции не проверяют входные данные — ожидается, что вызывающий код передаёт корректные значения.
3. **Строковый ID**: Возвращаемый ID — строка, а не число. Это важно для фронтенда.
4. **title_user**: Объединяет заголовок и логин — специфичное требование задания 5.
