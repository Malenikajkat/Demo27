# Документация: app/blueprints/auth.py

## Назначение

Файл `app/blueprints/auth.py` реализует **API авторизации** для приложения Demo27. Содержит JSON-эндпоинты для входа, регистрации и получения данных текущего пользователя. Отличается от `web.py` тем, что работает с JSON-данными, а не с HTML-страницами.

## Blueprint

```python
auth_bp = Blueprint("auth", __name__)
```

Регистрируется в `app/__init__.py` с префиксом `/api/auth`:
```python
app.register_blueprint(auth_bp, url_prefix="/api/auth")
```

## Маршруты (Endpoints)

### 1. `POST /api/auth/login` — Авторизация

**Функция**: `login()`

**Тело запроса**:
```json
{
    "login": "admin",
    "password": "password123"
}
```

**Ответы**:

| Статус | Условие | Тело |
|--------|---------|------|
| 400 | Нет login/password | `{"error": "Bad Request", "message": "Поля login и password обязательны"}` |
| 401 | Неверный логин/пароль | `{"error": "Unauthorized", "message": "Неверный логин или пароль"}` |
| 403 | Аккаунт заблокирован | `{"error": "Forbidden", "message": "Вы заблокированы"}` |
| 200 | Успешный вход | `{"message": "...", "user_id": 1, "login": "admin", "role": "Администратор"}` |

**Логика**:
1. Парсит JSON-тело запроса
2. Валидация обязательных полей
3. Поиск пользователя по логину
4. Проверка пароля через `verify_password()`
5. Если пользователь найден, но пароль неверный:
   - Увеличивает `failed_attempts` на 1
   - При 3+ попытках устанавливает `is_blocked = True`
   - Сохраняет в БД
6. Если заблокирован — возвращает 403
7. При успешном входе:
   - `login_user(user)` — создаёт сессию
   - Сбрасывает `failed_attempts = 0`
   - Возвращает данные пользователя

**Пример curl**:
```bash
curl -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"login":"admin","password":"admin123"}'
```

### 2. `GET /api/auth/me` — Данные текущего пользователя

**Функция**: `get_current_user()`

**Заголовки**: Требует авторизованной сессии

**Ответы**:

| Статус | Условие | Тело |
|--------|---------|------|
| 401 | Не авторизован | `{"error": "Unauthorized", "message": "Пользователь не авторизован"}` |
| 200 | Успешно | `{"user_id": 1, "login": "admin", "role": "Администратор", "is_blocked": false}` |

**Логика**:
1. Проверяет `current_user.is_authenticated`
2. Возвращает данные текущего пользователя

**Пример curl**:
```bash
curl -X GET http://localhost:5000/api/auth/me \
  -H "Cookie: session=..."
```

### 3. `POST /api/auth/register` — Регистрация

**Функция**: `register()`

**Тело запроса**:
```json
{
    "login": "newuser",
    "password": "securepass",
    "role": "Пользователь"
}
```

**Ответы**:

| Статус | Условие | Тело |
|--------|---------|------|
| 400 | Нет login/password | `{"error": "Bad Request", "message": "Необходимо указать login и password"}` |
| 400 | Пользователь существует | `{"error": "Bad Request", "message": "Пользователь 'newuser' уже существует"}` |
| 201 | Успешная регистрация | `{"message": "...", "user_id": 2, "login": "newuser", "role": "Пользователь"}` |

**Логика**:
1. Парсит JSON-тело
2. Валидация обязательных полей
3. Проверка уникальности логина
4. Хеширование пароля через `hash_password()`
5. Создание пользователя с ролью "Пользователь" (по умолчанию)
6. Сохранение в БД

**Пример curl**:
```bash
curl -X POST http://localhost:5000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"login":"newuser","password":"securepass"}'
```

## Сравнение с web.py

| Характеристика | `auth.py` (JSON API) | `web.py` (HTML) |
|----------------|---------------------|-----------------|
| Формат данных | JSON | HTML-формы |
| Авторизация | Сессия (Cookie) | Сессия (Cookie) |
| Ошибки | JSON с кодами 400/401/403 | Flash-сообщения |
| Перенаправление | Нет (только JSON) | Да, по ролям |
| Капча | Нет | Да (временно отключена) |

## Ключевая логика

### Безопасность
- **Хеширование паролей**: `hash_password()` для новых пользователей, `verify_password()` для проверки
- **Блокировка аккаунта**: После 3 неудачных попыток входа
- **Проверка уникальности**: Предотвращает дублирование логинов
- **Стандартная роль**: Новые пользователи получают роль "Пользователь"

### Статусы HTTP
| Код | Значение | Использование |
|-----|----------|---------------|
| 200 | OK | Успешный вход |
| 201 | Created | Успешная регистрация |
| 400 | Bad Request | Ошибка валидации |
| 401 | Unauthorized | Неверные учётные данные |
| 403 | Forbidden | Аккаунт заблокирован |

## Важные замечания

1. **Без капчи**: В отличие от `web.py`, API не использует капчу.
2. **Без роутинга**: Не перенаправляет по ролям — возвращает JSON с данными пользователя.
3. **Сессия**: Использует те же cookie-сессии, что и `web.py`.
4. **Регистрация**: Любой может зарегистрироваться — нет ограничений по роли (кроме "Пользователь" по умолчанию).
5. **Блокировка**: Общая логика блокировки с `web.py` — счётчик `failed_attempts` общий.
