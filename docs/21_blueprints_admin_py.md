# Документация: app/blueprints/admin.py

## Назначение

Файл `app/blueprints/admin.py` реализует **API для админ-панели управления пользователями**. Содержит эндпоинты для CRUD-операций с пользователями с обязательной проверкой роли "Администратор".

## Blueprint

```python
admin_bp = Blueprint("admin", __name__)
```

Регистрируется с префиксом `/api/admin`.

## Вспомогательная функция

### `_require_admin()`

Проверяет права администратора. Возвращает `None` если проверка пройдена, иначе — JSON-ответ с ошибкой.

**Проверки**:
1. Авторизация: `current_user.is_authenticated`
2. Роль: `current_user.role == "Администратор"`

**Ответы**:
| Статус | Условие | Тело |
|--------|---------|------|
| 401 | Не авторизован | `{"error": "Unauthorized", "message": "Необходима авторизация"}` |
| 403 | Не администратор | `{"error": "Forbidden", "message": "Доступ запрещён"}` |

## Маршруты (Endpoints)

### 1. `GET /api/admin/users/` — Список пользователей

**Функция**: `list_users()`

**Декораторы**: `@login_required` + `_require_admin()`

**Ответ 200**:
```json
{
    "users": [
        {
            "user_id": 1,
            "login": "admin",
            "role": "Администратор",
            "is_blocked": false,
            "failed_attempts": 0,
            "created_at": "2025-01-15T10:30:00"
        }
    ]
}
```

### 2. `POST /api/admin/users/` — Создание пользователя

**Функция**: `create_user()`

**Декораторы**: `@login_required` + `_require_admin()`

**Тело запроса**:
```json
{
    "login": "newuser",
    "password": "securepass",
    "role": "Пользователь"
}
```

**Обязательные поля**: `login`, `password`

**Валидация**:
- Логин не пустой
- Пароль не пустой
- Логин уникален
- Роль: "Администратор" или "Пользователь"

**Ответ 201**:
```json
{
    "message": "Пользователь 'newuser' создан",
    "user_id": 2
}
```

### 3. `PUT /api/admin/users/<user_id>` — Обновление пользователя

**Функция**: `update_user(user_id)`

**Декораторы**: `@login_required` + `_require_admin()`

**Тело запроса** (все поля опциональны):
```json
{
    "role": "Администратор",
    "is_blocked": false
}
```

**Логика**:
- Обновляет `role` (если передано)
- Обновляет `is_blocked` (если передано)
- При разблокировке сбрасывает `failed_attempts = 0`

**Ответ 200**:
```json
{
    "message": "Данные обновлены"
}
```

### 4. `DELETE /api/admin/users/<user_id>` — Удаление пользователя

**Функция**: `delete_user(user_id)`

**Декораторы**: `@login_required` + `_require_admin()`

**Дополнительная проверка**:
```python
if user_id == current_user.user_id:
    return jsonify({"error": "Bad Request", "message": "Нельзя удалить себя"}), 400
```

**Ответ 200**:
```json
{
    "message": "Пользователь 'username' удалён"
}
```

## Ключевая логика

### Защита ролей
Все эндпоинты защищены двойной проверкой:
1. `@login_required` — пользователь должен быть авторизован
2. `_require_admin()` — роль должна быть "Администратор"

### Безопасность
- **Нельзя удалить себя**: Защита от случайного удаления текущего администратора
- **Валидация роли**: Только "Администратор" или "Пользователь"
- **Хеширование пароля**: `hash_password()` при создании
- **Уникальность логина**: Проверка перед созданием

### Сброс блокировки
При установке `is_blocked = False` автоматически сбрасывается `failed_attempts = 0`.

## Важные замечания

1. **Двойная защита**: Все эндпоинты имеют `@login_required` И `_require_admin()`.
2. **Защита от self-delete**: Нельзя удалить текущего пользователя.
3. **Полный CRUD**: Все 4 операции (GET, POST, PUT, DELETE).
4. **Сброс счётчика**: Разблокировка сбрасывает failed_attempts.
5. **Целочисленный ID**: user_id — INTEGER (не UUID), поэтому `<int:user_id>`.
