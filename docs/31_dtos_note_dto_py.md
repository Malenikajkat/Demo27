# Документация: app/dtos/note_dto.py

## Назначение

Содержит **Dataclass NoteDTO** для сериализации заметок с **трансформацией данных** согласно требованиям задания 5 (API.md).

## Класс `NoteDTO`

### Поля

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `str` | ID в формате "00001" |
| `title_user` | `str` | Заголовок + логин автора |
| `content` | `str` | Текст заметки |
| `formatted_date` | `str` | Дата в формате "ДД.ММ.ГГГГ" |

### Методы

#### `from_model(cls, note, login) -> NoteDTO`

Создаёт DTO из модели `Note` с трансформацией полей.

**Параметры**:
| Параметр | Тип | Описание |
|----------|-----|----------|
| `note` | `Note` | Объект модели |
| `login` | `str` | Логин автора |

**Трансформации**:
| Поле | Преобразование | Функция |
|------|---------------|---------|
| `id` | `note.note_id` → "00001" | `format_note_id()` |
| `title_user` | `"Заголовок - login"` | f-string |
| `content` | Без изменений | Прямое копирование |
| `formatted_date` | `datetime` → "15.03.2025" | `format_date()` |

**Пример**:
```python
dto = NoteDTO.from_model(note_obj, "admin")
# dto.id = "00001"
# dto.title_user = "Моя заметка - admin"
# dto.content = "Текст..."
# dto.formatted_date = "15.03.2025"
```

### Особенности

- **Нет `to_dict()`**: Dataclass не использует `asdict()` — поля уже в нужном формате
- **Зависит от utils**: Использует `format_note_id()` и `format_date()` из `app/utils.py`
- **Требования API.md**: Формат полностью соответствует заданию 5

## Зависимости и связи

| Элемент | Тип связи | Описание |
|---------|-----------|----------|
| `app/models.py` | Использует | Модель `Note` |
| `app/utils.py` | Использует | `format_note_id()`, `format_date()` |
| `app/blueprints/notes.py` | Использует | `build_note_response()` (альтернатива) |
| `Zadanie/API.md` | Требования | Формат ответа |

## Важные замечания

1. **Дублирование**: Аналогичная логика в `app/utils.py` (`build_note_response`).
2. **Трансформация**: Поля преобразуются при создании DTO, а не хранятся в БД.
3. **Строковый ID**: ID — строка "00001", а не число 1.
