# Карта репозитория Demo27

**Дата:** 24.11.2026  
**Объект:** Demo27 — веб-приложение производственной информационной системы на Flask.

## 1. Назначение проекта

Проект реализует веб-интерфейс и API для работы с клиентами, продукцией, материалами, технологическими операциями, спецификациями, заказами покупателей, заказами на производство, пользователями и заметками. Серверная часть построена на Flask и Flask-SQLAlchemy; в конфигурации предусмотрена PostgreSQL.

## 2. Структура каталогов

| Путь | Назначение |

| `app/views/` | Зарегистрированные API-представления, преимущественно на базе `MethodView` |
| `app/services/` | Сервисный слой бизнес-операций |

| `app/utils.py` | Вспомогательные функции формирования ответов |
| `database/schema.sql` | SQL-схема PostgreSQL, ограничения, индексы и демонстрационные данные |
| `database/order_cost_query.sql` | SQL-запросы и функция расчёта стоимости заказа |

| `tests/` | Pytest-тесты авторизации и API заметок |
| `run.py` | Точка запуска приложения |
| `requirements.txt` | Список runtime-зависимостей |

## 3. Фактическая регистрация маршрутов

В `app/__init__.py` регистрируются `web_bp`, `auth_bp` и Blueprint-объекты, импортируемые из `app/views/`. Функциональные модули `app/blueprints/clients.py`, `materials.py`, `operations.py`, `products.py`, `production_orders.py`, `specifications.py`, `notes.py` и `admin.py` в текущей фабрике напрямую не регистрируются. Это две параллельные реализации API; при дальнейшем развитии проекта существует риск исправлять неиспользуемый маршрут или получить различия в поведении.

## 4. Как запустить проект

1. Установить Python и PostgreSQL.
2. Создать виртуальное окружение: `python -m venv .venv`.
3. Активировать окружение и установить зависимости: `pip install -r requirements.txt`.
4. Создать `.env` и задать `DATABASE_URL` и `SECRET_KEY`. Для PostgreSQL URL должен указывать на доступную базу данных.
5. Запустить приложение командой `python run.py`.
6. Для тестирования установить тестовые/статические инструменты из `requirements-dev.txt` и запустить `pytest -q`.

В исходном варианте `run.py` запускает сервер на `0.0.0.0:5000` с `debug=True`. Это небезопасно для публикации приложения; в ходе исправлений точка запуска переведена на настройки окружения.

## 5. Что отсутствует в полученном архиве

В исходном архиве не обнаружены `.git/`, `README.md`, каталоги `docs/` и `scripts/`, файл `postman_collection.json`, файл `er_diagram.pdf` и готовые миграции. В ходе ревью создана отдельная SQL-миграция `database/migrations/20261124_review_fixes.sql`; полноценное окружение Alembic в исходном проекте по-прежнему отсутствует. Поэтому история предыдущих коммитов не восстанавливается, Postman-прогон выполнить по приложенной коллекции невозможно, а ER-диаграмму сверить нельзя. Для проверки структуры БД использованы только ORM-модели и `database/schema.sql`.

- `compileall` завершился успешно: синтаксических ошибок Python не обнаружено.

- Для полноценной проверки PostgreSQL, миграций и HTTP-сценариев требуется среда с установленными зависимостями и доступной БД.
