# Итоговый отчёт по ревью Demo27

**Дата:** 24.11.2026  
**Ветка:** `review/student`  
**Объект:** исходный архив Demo27 (без `.git/` и части материалов из задания).

## 1. Краткое заключение

В проекте реализована понятная слоистая структура Flask-приложения: ORM-модели, DTO, репозитории, сервисы, API-представления и HTML-интерфейс. Синтаксис Python корректен, парольные значения в прикладном коде хешируются, а SQL-слой в целом использует SQLAlchemy.

Вместе с тем до ревью проект содержал несколько рисков, препятствующих безопасной эксплуатации: публичная регистрация позволяла запросить административную роль; значительная часть API не имела общей проверки авторизации; заметки могли читаться без входа и без ограничения владельца; секретные параметры имели небезопасные значения по умолчанию; в интерфейсе заметок использовалась небезопасная вставка пользовательского содержимого в HTML. Дополнительно выявлены расхождения ORM/SQL и формул расчёта скидки.

## 3. Исправления, внесённые в рамках практики

В полученном ZIP уже присутствовали правки исходного кода. Поскольку в ZIP нет `.git/`, точные коммиты этих правок невозможно восстановить. Ниже перечислены правки, которые уже включены в переданный снимок:

1. **Безопасная регистрация:** публичная регистрация не может назначить роль администратора; добавлена проверка типов входных данных и удалено дублирование чтения JSON.
2. **Защита API:** введена общая проверка авторизации для class-based API и endpoint заметок; выдача заметок ограничена текущим пользователем.
3. **Защита от stored XSS в заметках:** динамические заголовки и тексты заметок выводятся через `textContent`; небезопасная вставка в HTML для этого сценария удалена.
4. **Конфигурация:** убраны production fallback-секрет и пароль БД; конфигурация выбирается по аргументу фабрики; production не выполняет `create_all`; debug/host/port задаются безопасно.
5. **Согласованность БД и входных данных:** добавлено поле связи production order в SQL-схему, ограничения уникальности цен синхронизированы, скидка рассчитывается одинаково в Python и SQL, демонстрационные хеши исправлены; некорректная или нестроковая дата заказа отклоняется с HTTP 400.

## 5. Ограничения и достоверность результата

- Исходный ZIP не содержал `.git/`; локальная Git-история создана с импортным базовым коммитом. Она не является продолжением истории GitHub.
- ZIP не содержал `postman_collection.json`, `er_diagram.pdf`, `scripts/` и исходного `docs/`.
- `compileall` прошёл успешно, но `pytest` не собрал тесты из-за отсутствующего Flask. Установка зависимостей не состоялась из-за сетевой недоступности PyPI.
- flake8/pylint/bandit/pip-audit не запускались. В `style_report.txt` приведён фактический результат альтернативной AST-проверки, а не имитация вывода этих инструментов.
- Ветка создана локально. Push и Pull Request не выполнены, поскольку в архиве нет Git remote, а подключённый GitHub-доступ в этой сессии отсутствует.
