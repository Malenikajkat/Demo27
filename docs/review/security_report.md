# Отчёт: безопасность

Дата: 24.11.2026. Область: `app/`, `web/`, `run.py`, конфигурация. Зависимости вынесены в `deps_report.md`.

## Метод
Ручной обзор + `bandit -r app run.py` (3 предупреждения: B104 в `run.py:9`, B311 ×2 в `puzzle_captcha.py`) + проверка эксплуатацией на тестовом экземпляре.

## Подтверждённые проверкой уязвимости

| Проверка | Результат |
|---|---|
| Аноним: GET /api/clients/, /api/products/, /api/sales-orders/, /api/production-orders/ | 200 — данные доступны без входа |
| Аноним: GET /api/admin/users/ | 302 на страницу входа (защищено, но редирект вместо JSON 401) |
| Аноним: POST /api/auth/register с `role: "Администратор"` | **201** — создан администратор |
| Обход пути `GET /image/..%2f.env` | 404 — обход не удался |

## Что сделано хорошо
- Пароли хранятся как PBKDF2-хеш с солью (werkzeug).
- `.env` в `.gitignore`, в истории репозитория секретов нет.
- ORM-запросы параметризованы; `logout` — только POST.
- Админ-операции проверяют роль и запрещают удалять самого себя.
